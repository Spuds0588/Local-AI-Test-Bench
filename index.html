1 · What are you testing?

Start with the run shape: one model, a comparison of several, or a chain of steps that can hand off between models.

Task type (what the prompt is judged as)

Max Tokens caps how long one answer may get, and it defaults to the bench maximum (2048) on purpose: generation still stops on its own at the model's end-of-sequence token, so a high cap never wastes work on a finished answer. Lower it only when you want to force a bounded reply — to keep a slow CPU model snappy, to stop a model that rambles/repeats, or to fit more models in memory at once. Lowering it truncates output mid-answer.

Tool-calling protocol: Needle 2 and FunctionGemma use their native tool formats. All other models receive the tool schemas in the system prompt and are asked to reply with a single JSON object {"function": "...", "arguments": {...}} (or {"function": null} if no tool fits).

Vision models run through Transformers.js (AutoProcessor + AutoModelForImageTextToText). Pick Vision as the mode, then choose vision models on step 2. The image never leaves your browser.

Build an ordered pipeline. Each step runs its own model (the same one again or a different one) and chooses what it receives from earlier steps — nothing, just the previous step, or every earlier step. Drop {{prev}} or {{step2}} into a prompt to place a prior answer exactly where you want it, and give a step expected keywords to grade it.

Comma/newline-separated keywords are matched case-insensitively against each output; a leading { is parsed as an expected tool call and scored function-then-arguments. Each run is graded ✅ pass / ⚠️ partial / ❌ fail and aggregated in the scoreboard below.
